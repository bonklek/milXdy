# Publication boundary

The author guide is a public rewrite of stable milXdy visual and interaction
principles. It does not reproduce internal operating material.

## Published

- host-owned rail/chrome and package-owned interior responsibilities;
- compact utility geometry, semantic token roles, and plural chrome/register
  guidance;
- light, dim, dark, system, forced-color, responsive, and accessibility rules;
- explicit state, lifecycle, motion, and sound contracts;
- public-source design observations with local/upstream labels;
- license-neutral local packaging plus the optional VPL upstream-promotion
  workflow; and
- current public App SDK package asset declarations plus a catalog provenance
  lockfile.

## Intentionally excluded

- local machine paths, worktree/release operations, and maintainer-only
  automation because they are not author-facing product contracts;
- internal planning history, prioritization discussion, and agent instructions
  because public guidance should state the resulting rule directly;
- personal data, credentials, private correspondence, and private browser state
  because they are never publication evidence;
- unpublished product decisions because a guide must not create accidental
  commitments;
- non-public reference material because readers could not independently inspect
  it;
- private source files or third-party media as bundled examples when they are
  unnecessary to teach the contributor workflow; and
- claims that a local user's asset is officially endorsed merely because it
  works in a custom build.

The exclusion list describes categories only. It does not reproduce sensitive
material.
