## Manual Firefox Load

1. Open Firefox.
2. Go to `about:debugging#/runtime/this-firefox`.
3. Click **Load Temporary Add-on**.
4. Select `dist/firefox/manifest.json`.
5. Open the extension background console.
6. Confirm no startup errors.

## Manual Firefox Smoke Test

Follow public `docs/FIREFOX_QA.md`, plus these private release checks:

- Popup opens and the current release's final tab layout renders.
- Settings changed in Firefox persist after extension reload.
- X/Twitter content bootstrap loads after route changes.
- Dynamic feature imports load from `features/*.js`.
- Remilia Wiki links and previews render.
- Postreader can read a post.
- OCR progresses past hidden-host loading and returns either text or a clear failure.
- RemiStats badges, poke controls, cooldown state, and incoming poke indicators render.
- RemiNet Chat connects, receives messages, and preserves minimized/side/height settings.
- Beetol auth/session status, cooldowns, and action states render.
- Miladymaxxer detection starts in Debug mode and writes diagnostics.
- ONNX model/WASM path loads or produces a clear documented Firefox limitation.
- Browser action badge updates do not throw in the background console.
- Notifications and context menus do not throw.

## Regression Rules

If Firefox fails:

1. Identify whether the issue is manifest/build-only, browser API compatibility, packaged asset path, CSP/WASM, or feature behavior.
2. Prefer small compatibility wrappers over feature rewrites.
3. Keep Chromium behavior unchanged unless the current code is clearly broken.
4. Document any Firefox-only limitation in public docs before release.
5. Re-run:

```powershell
npm.cmd run typecheck
npm.cmd run build:all
npm.cmd run lint:firefox
```

6. If shared runtime code changed, reload `dist/chromium` in Chrome and smoke test the touched feature.
