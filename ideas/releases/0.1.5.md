Public theme: Firefox compatibility, RemiNet polish, screenshot sharing, and RemiNet/Beetle profile identity.

## Release Goals

- Make Maxxer behavior more configurable.
- Prepare all feature release details before the post-freeze Firefox compatibility pass.
- Complete the Firefox smoke-test pass after Chromium testing and code freeze.
- Keep performance bounded.
- Add replies to the RemiChat interface.

## Current Code Inventory

Release baseline:

- `v0.1.5` shipped from commit `96c498e59cbb3e2b97769db327a4e315f91167d3`.
- Main touched areas: popup UI, RemiNet/Beetol auth, RemiNet Chat, RemiStats/pokes, Beetol hunter panel, Miladymaxxer, Postreader placement, visual theme settings, Firefox packaging, docs, and release assets.

Implemented or partially implemented locally:

- Popup navigation was compressed to five tabs: Main, Wiki Links, Audio, RemiNet, and Milady Maxxer.
- Health/diagnostic reporting moved into Main rather than a separate tab.
- Audio tab consolidates Postreader voice/playback settings, RemiStats sounds, Milady Maxxer sounds, and appearance interaction sounds.
- Postreader voice URI control changed from free text to a populated browser voice dropdown.
- RemiliaNET direct username/password login form was removed; connector auth now relies on opening remilia.net and retrying browser-session auth.
- RemiNet/Beetol logout now disconnects milXdy from automatic browser-session reuse until Retry session is clicked again.
- RemiNet Chat reply UI is implemented: reply action, reply preview, reply context rendering, and `in_reply_to_id` message payload support.
- RemiNet Chat reactions gained extra emoji options and reaction tooltips with available user names.
- RemiNet Chat can hydrate inline video attachments as data URLs, not only images.
- RemiNet Chat profile lookup now has local cache/miss caching and skips profile lookup when an X connection is already present.
- RemiStats poke button now uses an outline hand asset and more X-native action-row styling.
- Poke cooldowns are stored locally and restored after refresh.
- Successful pokes can emit a Miladymaxxer interaction credit for tracked Milady accounts.
- Incoming poke flags gained an optional gold visual treatment setting.
- Beetol hunter panel gained persistent cooldown state, hunt charge display, richer action states, and improved exhausted/cooldown visuals.
- RemiStats profile banner work is present: trophy shelf rendering, banner stage transitions, random Banners NFT mode, banner cycle button, and spin sound.
- RemiStats profile banner cycling now uses custom lever artwork and a loading state.
- Background fetch support and manifest host permission were added for `https://miladymaker.net/banners/nft/*`, restricted to numeric Banners NFT PNG URLs.
- Tweet PNG export is present from X/Twitter share actions, with local PNG rendering, clipboard/download/share paths, and quote/media/stat rendering.
- Visual theme settings gained `maxMediaHeight`, `incomingPokeGold`, and Tweet PNG export controls.
- Max visual profile now marks tweet headers/metadata rows to avoid overflow and adds configurable max media height.
- Unread notification tint now uses detected unread markers rather than broadly styling all notification articles.
- Shared X/Twitter scanner now extracts handles, pauses safety scans while the document is hidden, and writes scanner diagnostics when enabled.
- Feature timing diagnostics are present for RemiStats, Miladymaxxer, Postreader, and Wiki processing when diagnostics are enabled.
- Miladymaxxer suppresses self profile badges when self-tracking is disabled and can credit RemiNet pokes.
- Postreader button placement now prefers the last action-row button instead of top tweet controls, reducing header clutter.

## Planned Features

### Firefox support integration

Labels: `browser-compat`, `experimental`.

Status:

- Build support exists locally.
- Do not claim Firefox support publicly until the shipped beta has passed the Firefox smoke test.

User-facing target:

- "Firefox beta compatibility" if the contributor branch passes local smoke tests after integration.

Validation areas:

- MV3 background behavior.
- `chrome.*`/`browser.*` API compatibility.
- Cookies permission and RemiNet auth behavior.
- Notifications.
- Context menus.
- Dynamic imports from extension URLs.
- Web accessible resources.
- OCR/WASM assets.
- ONNX/model assets.
- X/Twitter content-script behavior.
- Popup layout and settings persistence.

Post-freeze checklist:

- Follow `ideas/releases/0.1.5-firefox-prep.md`.
- Preserve Chromium behavior while fixing Firefox compatibility issues.
- Update docs with exact Firefox load instructions and known limits.

### Complete non-Milady minimization

Labels: `maxxer`, `performance`.

Rules:

- Minimize non-Milady avatars/profile pictures when Maxxer is active.
- Do not minimize users with RemiStats beetle stats when the bridge is enabled.
- Respect whitelist and manual Milady handles.
- Make minimization reversible from settings.

Risk:

- False negatives can be visually harsh.
- Need easy disable/undo path.

### RemiNet Chat replies

Labels: `reminet`, `chat`, `ux`.

Goal:

- Enable replies inside the RemiChat interface.

Desired UX:

- User can reply to a specific RemiChat message without leaving the chat surface.
- Reply context stays compact enough for the sidebar/chat layout.
- The reply affordance feels consistent with existing reaction, poke, attachment, and composer controls.

Implementation notes:

- Reuse existing RemiNet Chat auth and message transport.
- Prefer existing upstream reply/thread fields if available.
- If upstream reply metadata is not exposed, keep the UI hidden rather than faking threaded state.

### Poke outline icon polish

Labels: `reminet`, `ux`.

Goal:

- Replace the poke pointing-finger icon with an empty outline icon that better matches native X action buttons.

Requirements:

- Preserve hover, disabled, sending, cooldown, error, and diagnostic states.
- Keep the icon recognizable at timeline and profile badge sizes.
- Avoid layout shifts in existing RemiStats badge groups.

### Unified Audio settings tab

Labels: `settings`, `postreader`, `ux`, `audio`.

Goal:

- Consolidate sound controls and TTS controls into one `Audio` tab.

Desired UX:

- RemiNet poke sounds, Postreader speech, and related voice/sound settings are grouped in one place.
- Existing settings migrate without resetting user preferences.
- The tab stays scannable and does not become a dumping ground for unrelated media controls.

### Beetle Game trophy shelf on X profiles

Labels: `beetol`, `reminet`, `ux`.

User-facing target:

- Optional profile-header/trophy shelf enhancement for RemiNet/Beetle accounts.

Open questions:

- Which endpoint exposes trophy shelf data?
- Does it work for accounts other than the signed-in user?
- How should empty shelves display?

### Optional banner randomizer

Labels: `identity`, `nft`, `ux`, `experimental`.

Goal:

- Let users optionally rotate banner visuals using banner NFT items as part of the trophy/profile identity update.

Desired UX:

- Off by default.
- User can enable the randomizer from settings.
- Clicking the banner surface opens the corresponding Blur listing when available.

Open questions:

- What source identifies eligible banner NFT items?
- Does the user need ownership proof or can this be a local visual picker?
- How are Blur listings resolved reliably?

### Tweet PNG from X share actions

Labels: `reminet`, `security`, `experimental`.

Goal:

- Add a user-initiated way to render a tweet as a local PNG from X/Twitter share actions.

Required before shipping:

- Verify copy/download/share behavior across supported Chromium versions.
- Verify quote/media/stat rendering with common tweet shapes.
- Add preview/review step.
- Warn about private information.
- Keep direct RemiNet upload blocked until a suitable endpoint/API and auth behavior are confirmed.

Hard rule:

- Never send or upload screenshots/PNGs automatically.
